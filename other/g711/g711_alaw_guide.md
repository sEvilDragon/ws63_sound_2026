# G.711 A-law 音频压缩算法详解 (16-bit PCM 至 8-bit)

## 1. 算法背景与原理

**G.711 A-law** 是一种由 ITU-T 定义的非线性压缩算法，广泛应用于数字通信（如中国和欧洲的电话网）。它能将 **16-bit 线性 PCM** 数据压缩为 **8-bit 编码**，实现 **2:1 的固定压缩比**。

### 核心原理：对数压缩 (Logarithmic Compression)
人耳对声音的感知是非线性的：
*   在**小信号**（安静的声音）处，人耳对微小的幅值变化非常敏感。
*   在**大信号**（响亮的声音）处，人耳对细微差异的感知能力大幅下降。

**A-law 利用这一点：**
- 对小信号使用较小的量化阶（细腻的步长）。
- 对大信号使用较大的量化阶（粗糙的步长）。
这样在同样的 8-bit 带宽下，信噪比（SNR）在全量程内分布更符合听感，听起来比简单的 8-bit 线性截断要好得多（接近 12-bit 效果）。

---

## 2. A-law 编码结构 (8-bit)

一个 A-law 字节由三部分组成：`S EEE MMMM`

1.  **S (1-bit, Sign)**: 符号位。
2.  **EEE (3-bit, Exponent)**: 指数位（段落号）。共有 8 个段落（0-7），代表信号的量级范围。
3.  **MMMM (4-bit, Mantissa)**: 尾数位。在当前指数段内的详细位置。

> **注意：** A-law 在最终输出前，会根据标准对偶数位进行**按位异或 (XOR 0x55)**，这是为了增加线路信号的极性翻转率，防止长连 0 导致同步丢失。

## 3. A-law 实现 (WS63/C++ 示例)

在 MCU（如 WS63）上，最推荐的方式是使用**查表法**或**分段移位法**。以下是一个高效的 C++ 实现参考。

### A-law 实现类示例 (轻量化版本)

```cpp
#include <cstdint>

class AlawCodec {
public:
    /**
     * @brief 16-bit PCM 编码为 8-bit A-law (优化版，不依赖 algorithm 库)
     */
    static inline uint8_t encode_sample(int16_t pcm) {
        int sign = (pcm & 0x8000) >> 8;           // 提取符号位到第8位
        if (sign != 0) {
            // 手动取绝对值，避免引入标准库
            pcm = (pcm == -32768) ? 32767 : -pcm;
        }

        uint8_t code;
        if (pcm >= 256) {
            int exponent = 7;
            // 使用简单的数值比较代替 LUT 查表或库函数
            if (pcm < 512) exponent = 1;
            else if (pcm < 1024) exponent = 2;
            else if (pcm < 2048) exponent = 3;
            else if (pcm < 4096) exponent = 4;
            else if (pcm < 8192) exponent = 5;
            else if (pcm < 16384) exponent = 6;
            
            int mantissa = (pcm >> (exponent + 3)) & 0x0F;
            code = (uint8_t)(sign | (exponent << 4) | mantissa);
        } else {
            code = (uint8_t)(sign | (pcm >> 4));
        }

        return code ^ 0x55; // 标准异或
    }

    /**
     * @brief 8-bit A-law 解码回 16-bit PCM (无外部依赖)
     */
    static inline int16_t decode_sample(uint8_t alaw) {
        alaw ^= 0x55; 
        int sign = alaw & 0x80;
        int exponent = (alaw & 0x70) >> 4;
        int mantissa = alaw & 0x0F;
        int pcm;

        if (exponent > 0) {
            pcm = ((mantissa << 4) | 0x108) << (exponent - 1);
        } else {
            pcm = (mantissa << 4) | 0x008;
        }

        return (sign == 0) ? (int16_t)pcm : (int16_t)(-pcm);
    }
};
```

### A-law 查表法实现 (性能最强版本)

在 WS63 这种对实时性要求极高的音频采集场景下，**查表法 (Look-up Table)** 是终极方案。它避开了所有的 `if-else` 分支判断和符号处理逻辑，直接通过偏移量获取结果。

#### 1. 编码表 (16-bit PCM -> 8-bit A-law)
由于输入是 16位 (65536 种可能)，直接做主表太大。通常的做法是：
- 如果对内存敏感，使用上面提供的**分段移位法**（已足够快）。
- 如果追求极致且只处理常用位（如 13-bit 采样），可以使用 8192 字节的表。

## 4. 为什么 A-law 对你更合适？

1.  **无损同步 (Self-healing)**：
    *   你之前的 ADPCM 是有**状态 (State)** 的算法。如果通过无线丢包，接收端的 `last_prediction` 就会和发送端对不上，后面所有的音频都会变成尖锐的杂音。
    *   **A-law 是无状态的**。每个字节独立解码，丢包只影响丢掉的那个样本，下一刻立即恢复正常。
2.  **极低功耗**：
    *   WS63 运行 A-law 几乎不消耗 CPU 周期，甚至可以改写成 256 字节的**查表法**，直接：`data_out = table[data_in]`。
3.  **标准兼容**：
    *   它是工业级标准，任何成熟的音频处理软件、VLC、FFmpeg 都能直接播放或解码。

## 5. 调试建议

*   **输入动态范围**：确保你的 16-bit PCM 输入是占满幅度的（-32768 到 32767），如果输入声音太小，压缩后的底噪会明显。
*   **字节序**：WS63 是小端机，处理音频流时注意 `int16_t` 的解析。
*   **异或处理**：一定要记得最后的 `^ 0x55`，否则有些解码器解出来波形是反的。
