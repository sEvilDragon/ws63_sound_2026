# CS43131 基于 PDF 的初始化指令与顺序说明

本文只做一件事：把 CS43131 数据手册里和你当前需求直接相关的初始化顺序整理成可执行的 IIC 指令表，不做代码层深度融合。

你的目标条件是：

- 希望用 40 MHz 晶振
- 需要可变采样率
- 初始采样率 44.1 kHz
- 固定双声道
- 固定 16-bit

先给结论：

## 1. 40 MHz 不能直接作为 CS43131 的晶振或 PLL 参考

这是 PDF 直接给出的硬限制，不是软件配置问题。

### 1.1 晶振模式限制

PDF 第 23 页 Table 3-16 写得很明确：

- Crystal oscillator frequency 只支持 22.5792 MHz 或 24.576 MHz

所以：

- 40 MHz 不能直接接 XTI/XTO 当晶振

### 1.2 PLL 参考时钟限制

PDF 第 45 页写明：

- PLL_REF source 输入范围是 9.6 MHz 到 26 MHz

所以：

- 40 MHz 也不能直接接到 XTI/MCLK 作为 PLL 参考输入

因此，如果你坚持 40 MHz 板级时钟，必须在板外先做分频或时钟合成，把它变成 CS43131 支持的频率后，再送给 CS43131。

## 2. 你这个需求在 PDF 下的正确实现路径

如果你要初始 44.1 kHz，最稳妥、最符合 PDF 的方案是：

1. 给 CS43131 单独提供 22.5792 MHz 晶振
2. 先按 44.1 kHz 家族启动
3. 如果后面要切到 48 kHz 家族，再切到 24.576 MHz 家族时钟

也就是说：

- 44.1 kHz 家族推荐内部 MCLK = 22.5792 MHz
- 48 kHz 家族推荐内部 MCLK = 24.576 MHz

## 3. IIC 控制口格式

### 3.1 默认器件地址

PDF 第 59 页 Table 4-12：

- ADR 直接下拉到 GND 时，最后两位地址是 00
- 默认 7-bit I2C 地址就是 0x30

### 3.2 单寄存器写帧格式

PDF 第 59 到 60 页说明，控制口写格式是：

1. 3 字节 MAP 地址
2. 1 字节 CONTROL BYTE
3. 1 字节 DATA

单字节寄存器写时：

- SIZE = 00，表示 8-bit 访问
- INCR = 0，表示不自增
- 所以 CONTROL BYTE = 0x00

因此，单寄存器写负载统一是：

MAP[23:16]  MAP[15:8]  MAP[7:0]  0x00  DATA

例如：

- 写 0x20052 = 0x04
- 实际发送负载就是 02 00 52 00 04

### 3.3 单寄存器读帧格式

PDF 第 60 到 61 页说明，读寄存器通常使用 preamble：

1. 先发 4 字节前导写：MAP[23:16], MAP[15:8], MAP[7:0], CONTROL BYTE
2. 然后 repeated start
3. 再读 1 字节

例如读取 0xF0000：

- 前导写负载：0F 00 00 00
- 然后读 1 字节

## 4. PDF 官方 44.1 kHz I2S 启动序列

PDF 第 74 到 76 页 Example 5-7 给的是：

- 22.5792 MHz 晶振
- ASP 作为 I2S Master
- 44.1 kHz
- 双声道
- 32-bit slot

这和你的目标最接近，所以应该以它为基础。

但是你要求的是 16-bit stereo，不是 32-bit slot，所以有几个寄存器值需要从 PDF 规则推导修改。

## 7. 你的 16-bit 双声道版本应该怎么改

这部分不是“瞎改”，而是按照 PDF 的串口时钟和位宽规则，从官方 32-bit 序列推出来的。

### 7.1 目标帧格式

双声道 16-bit I2S：

- 左声道 16 bit
- 右声道 16 bit
- 每帧共 32 个 SCLK

因此：

- SCLK = 44.1 kHz x 32 = 1.4112 MHz

### 7.2 ASP 分频计算

PDF 的 ASP 时钟关系是：

- ASP_SCLK = MCLK_INT x N / M

在 22.5792 MHz 内部 MCLK 下，希望得到 1.4112 MHz：

- N = 1
- M = 16

因为：

- 22.5792 / 16 = 1.4112

### 7.3 16-bit 时需要替换的寄存器

只需要改下面这些值，其余顺序可以沿用官方 Example 5-7。

#### 7.3.1 0x1000C Serial Port Sample Bit Size

PDF 第 114 页：

- XSP_SPSIZE = 01 表示 24 bits
- ASP_SPSIZE = 10 表示 16 bits

所以：

- 0x1000C = 0x06

IIC 负载：

- 01 00 0C 00 06

#### 7.3.2 0x40012, 0x40013 ASP denominator

要把 M 从 8 改成 16：

- 0x40012 = 0x10
- 0x40013 = 0x00

IIC 负载：

- 04 00 12 00 10
- 04 00 13 00 00

#### 7.3.3 0x40014, 0x40015 LRCK high time

16-bit 双声道总帧长 32 SCLK，50/50 模式下每相 16 SCLK。

按 PDF 规则：

- ASP_LCHI = 15

所以：

- 0x40014 = 0x0F
- 0x40015 = 0x00

IIC 负载：

- 04 00 14 00 0F
- 04 00 15 00 00

#### 7.3.4 0x40016, 0x40017 LRCK period

总帧长 32 SCLK，所以：

- ASP_LCPR = 31

因此：

- 0x40016 = 0x1F
- 0x40017 = 0x00

IIC 负载：

- 04 00 16 00 1F
- 04 00 17 00 00

#### 7.3.5 0x5000A, 0x5000B 通道位宽

PDF 第 123 页：

- RES = 01 表示 16-bit
- CH1_AP = 0，CH2_AP = 1
- EN = 1

所以：

- 0x5000A = 0x05
- 0x5000B = 0x0D

IIC 负载：

- 05 00 0A 00 05
- 05 00 0B 00 0D

### 8.2 如果要改成 ASP Slave 模式

这里要先把一个概念分开：

- ASP Master / Slave 只决定 BCLK 和 LRCK 由谁产生
- 它不自动改变 CS43131 自己内部主时钟的合法性

也就是说：

- 改成 ASP Slave 的含义，是让 WS63 或其他主控输出 BCLK 和 LRCK
- CS43131 只负责按外部送进来的串口时序取数
- 但 CS43131 内部仍然需要一个它自己支持的合法时钟来源来驱动 DAC 内部处理链路

所以，ASP Slave 能解决的是“不要让 CS43131 自己生 BCLK/LRCK”，不能单独解决“40 MHz 直接喂给 CS43131 当内部时钟”这个问题。

#### 8.2.1 改成 Slave 后，整体思路怎么变

当前第 8.1 节这套序列，是典型的：

1. CS43131 自己起 XTAL
2. 内部 MCLK 切到 XTAL
3. 自己按 N/M/LRCK 参数生成 BCLK 和 LRCK
4. ASP 作为 Master 往外送时钟

如果改成 ASP Slave，思路就变成：

1. 外部主控负责提供 BCLK 和 LRCK
2. CS43131 不再输出 ASP 时钟
3. CS43131 只需要知道外部串口格式是什么
4. 通道格式、位宽、PCM 路径、耳放路径仍然要正常配置

因此，Slave 模式下最关键的变化不是 PCM 部分，而是 ASP 时钟生成这部分要退出。

#### 8.2.2 Slave 模式下哪些配置仍然是必须的

下面这些寄存器，即使改成 ASP Slave，通常仍然要保留，因为它们描述的是“收到的数据该怎么解释”和“模拟输出链路怎么工作”：

1. 0x1000B 采样率配置
2. 0x1000C ASP/XSP 位宽配置
3. 0x40019 串口帧格式配置，例如 I2S、50/50、1-bit delay
4. 0x50000、0x50001 通道起点
5. 0x5000A、0x5000B 声道相位、位宽、使能
6. 0x90000 到 0x90004 PCM 滤波、音量、路径控制
7. 0xB0000、0x80000 这些耳放和输出幅度设置
8. Pop-free 上电序列，也就是 0x10010、0x80032 和后面的电源打开流程

换句话说：

- Slave 模式不是把第 8.1 节砍掉重来
- 而是主要改“时钟谁来出”，PCM 和 HP 这一大段仍然基本保留

#### 8.2.3 Slave 模式下哪些主模式命令要删除或重新确认

下面这些是当前 Master 方案中特有，改成 Slave 后要重点处理的部分：

1. 0x40018 当前写的是 0x1C，说明是 ASP Master
2. 0x1000D 当前写的是 0x02，作用是使能 ASP 主模式时钟输出
3. 0x40010 到 0x40017 这一组 N/M/LRCK 生成寄存器，在 Slave 模式下不再承担“对外生时钟”的职责

其中最关键的是：

- 0x40018 必须从 Master 改成 Slave
- 0x1000D 这一步通常不应再使能时钟输出

对于 0x40010 到 0x40017：

- 在 Master 模式下，它们决定 CS43131 自己生成的 BCLK/LRCK
- 在 Slave 模式下，外部已经提供 BCLK/LRCK，这组寄存器通常不再是决定性配置
- 但是否可以完全不写，最好以你手上的 PDF 对 0x40018 寄存器位定义为准

保守做法是：

1. 先把 0x40018 切成 Slave
2. 禁用 0x1000D 的主模式时钟输出
3. 先保留 0x40010 到 0x40017，不把它们当成关键时钟配置来依赖
4. 等实际验证后，再决定是否精简掉这组寄存器

#### 8.2.4 Slave 模式下，第 8.1 节顺序应如何调整

如果你已经有外部主控输出 BCLK/LRCK，那么第 8.1 节里可以这样理解：

必须保留：

1. 步骤 5 到 6，采样率和位宽
2. 步骤 16 到 29，I2S 格式、通道、PCM、HP 相关配置
3. 步骤 38 到 45，Pop-free 和 ASP/HP 上电流程

需要修改：

1. 步骤 15，0x40018 不能再保持 Master 配置

通常不再需要：

1. 步骤 37，0x1000D 使能 ASP 时钟输出

可能不再关键：

1. 步骤 7 到 14，这组 ASP N/M/LRCK 生成参数

是否还能保留 XTAL 相关步骤，要分情况：

1. 如果 CS43131 仍然有合法内部时钟来源，例如 22.5792 MHz 或 24.576 MHz，那么 XTAL / MCLK 相关步骤仍可能需要
2. 如果你只是把 ASP 改成 Slave，但 CS43131 内部时钟来源没有合法化，那么仍然可能不能正常工作

#### 8.2.5 对你“40 MHz”这个场景，Slave 模式到底有什么帮助

如果你的 40 MHz 是 WS63 自己的系统时钟，那么改 ASP Slave 的意义是：

- WS63 可以利用自己的时钟系统去生成外部 I2S 串口时序
- CS43131 不必再自己当 ASP Master

这时，40 MHz 不再直接参与“CS43131 生 BCLK/LRCK”这件事。

但你仍然要确认另一件事：

- CS43131 内部到底用什么时钟做 DAC 内部处理

如果答案仍然是：

- 直接把 40 MHz 接到 CS43131 的 XTAL 或 PLL 输入

那还是不对，因为这违反前面第 1 节的时钟输入限制。

所以更准确的结论是：

- ASP Slave 可以让 CS43131 跟随外部 BCLK/LRCK 工作
- 但 40 MHz 仍然不应直接作为 CS43131 的 XTAL/PLL 参考

#### 8.2.6 最实用的改法建议

如果你准备从当前 Master 版本切到 Slave，建议按下面顺序做：

1. 保留 PCM、通道、音量、Pop-free、HP 上电相关命令不动
2. 先把 0x40018 从 Master 改成 Slave
3. 去掉 0x1000D 这条“使能 ASP 时钟输出”命令
4. 外部主控先稳定输出 BCLK、LRCK、SDIN，再给 CS43131 放音
5. 再决定是否精简 0x40010 到 0x40017 这一组 Master 时钟生成参数

如果后面你要落到代码层面，那么可以把当前初始化理解成两层：

1. 串口模式层
  这里从 ASP Master 改成 ASP Slave
2. 模拟播放层
  PCM、HP、Pop-free 上电逻辑基本不变

这一点非常重要，因为它决定了你不是“重写一整套驱动”，而是在现有初始化流程里替换掉主模式时钟生成部分。

- 48 kHz
- 96 kHz

### 9.3 切采样率顺序

PDF 第 94 页 Example 5-16 的核心思路是：

1. 先关 PCM
2. 把 MCLK source 切到 RCO
3. 再切目标 MCLK 频率
4. 重新配置 ASP sample rate、bit size、N/M、LRCK period
5. 再切回 Direct MCLK 或 PLL
6. 再重新上电 ASP 和 HP

不要在正在出声时直接硬切 MCLK，否则会有爆音。

对你现在这个 16-bit 双声道配置来说，好消息是：
44.1 和 48 在串口格式上几乎一样。
因为两者都是 2 声道 × 16 bit = 32 个 BCLK 每帧，所以这些寄存器其实不用变：

- 0x1000C = 0x06
- 0x40010 = 0x01
- 0x40011 = 0x00

真正要变的核心只有两类：

1. 采样率寄存器
- 44.1 kHz 时：0x1000B = 0x01
- 48 kHz 时：0x1000B = 0x02

2. 内部 MCLK 来源
- 44.1 家族要 22.5792 MHz
- 48 家族要 24.576 MHz

你中途从 44.1 切 48，正确顺序建议这样做：

1. 先静音或先做 PCM power-down
原因：
PDF 明确说切 MCLK source 时如果 DAC 正在工作，会有可闻杂音。

2. 把 MCLK source 临时切到 RCO
寄存器：
0x10006 = 0x06
意思：
先脱离当前的 22.5792 XTAL 时钟域。

3. 等至少 150 us

4. 准备目标 MCLK = 24.576 MHz
这里分两种情况。

情况 A：你板上本来就有合法的 24.576 MHz 直时钟
那就走直时钟模式：
- 先把 0x10006 写成 0x02，表示目标内部频率切到 24.576，但 source 还在 RCO
- 后面真正切回直时钟时，用 0x10006 = 0x00

情况 B：你板上只有 22.5792 MHz 晶振
那就要走 PLL，把 22.5792 转成 24.576。
按 PDF 里的 PLL 配置，寄存器是：

- 0x20000 = 0xF2
- 0x40002 = 0x03
- 0x30008 = 0x08
- 0x30002 = 0x00
- 0x30003 = 0xF7
- 0x30004 = 0x06
- 0x30005 = 0x44
- 0x3001B = 0x01
- 0x3000A = 0x8B
- 先读 0xF0000 清状态
- 0xF0010 = 0xE1
- 0x30001 = 0x01 启动 PLL
- 轮询 0xF0000，等 PLL_READY_INT

PLL ready 之后，把 MCLK source 切到 PLL：
- 0x10006 = 0x01

这表示：
内部 MCLK = 24.576 MHz，来源 = PLL。

5. 把采样率改成 48 kHz
只需要：
- 0x1000B = 0x02

6. 如果你之前关了 ASP/HP，就按原来的上电顺序再打开
也就是：
- 打开 ASP
- 打开 HP/DAC
- 恢复 pop-free 相关寄存器

你可以把它理解成一句话：

从 44.1 切到 48，本质不是“改采样率”，而是“换时钟家族”。

如果再压缩成最实用版，就是：

44.1 → 48 最小思路：
1. 静音/关 PCM
2. 0x10006 = 0x06，切到 RCO
3. 准备 24.576 MHz
4. 如果用 PLL，先配置 PLL 并等 ready
5. 0x10006 = 0x01 或 0x00，切到 24.576 家族
6. 0x1000B = 0x02
7. 重新开 ASP/HP

还有一个很重要的现实问题：
如果你的硬件真的是 40 MHz，而且没有外部再分频或合成出合法时钟，那么你依然不能直接切到 48 家族。因为 40 MHz 既不能直接进 XTAL，也不能直接做 PLL 参考。这个限制在 48 kHz 场景下也一样成立。

你现在这个场景里，最实用的两种方案是：

1. 板上有 22.5792 MHz 晶振，同时允许开 PLL
这样你就能从 44.1 家族切到 48 家族。

2. 板上额外提供 24.576 MHz 直时钟
这样切 48 会更干净，流程也更简单。
