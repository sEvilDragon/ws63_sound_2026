# TTP229 触摸控制说明

控制端使用 TTP229-BSF 的 8 个触点组成滑条，并使用 A、B、C 三个独立功能键。实现位于：

- `realize/ttp229/`：两线串行读取、滑条位置计算、功能键消抖
- `realize/ui_task/`：按键功能和 `spi_settings_t` 参数更新

## 1. 当前功能

触摸控制只保留以下功能：

| 输入 | 功能 |
|---|---|
| A 短按 | 循环切换滑条目标：模式 → 音量 → 亮度 → 模式 |
| B 短按 | 打开或关闭热点 |
| C 短按 | 打开或关闭网络 |
| 滑条 | 按左右滑动的相对增量修改当前目标 |

不再包含 MAIN/CONFIG 双层状态、滑动手势、长按微调和低音调节。

热点和网络分别切换：B 修改热点时保留当前网络状态，C 修改网络时保留当前热点状态。

功能键确认后会异步请求语音模块播报，滑条连续移动不会重复请求，避免占满播报队列：

- A：根据切换后的目标播报“模式选择 / 音量调节 / 亮度调节”
- B：根据切换后的状态播报“打开热点 / 关闭热点”
- C：根据切换后的状态播报“打开网络 / 关闭网络”

## 2. 相对滑动行为

A 默认选择“模式”，每次短按切到下一个目标。

| 当前目标 | 向左滑 | 向右滑 |
|---|---|---|
| 模式 | 切到上一个：DLNA ← SLE ← 无模式 | 切到下一个：无模式 → SLE → DLNA |
| 音量 | 按滑动距离减小，最低 0 | 按滑动距离增大，最高 100 |
| 亮度 | 按滑动距离减小，最低 0 | 按滑动距离增大，最高 100 |

模式循环首尾相接，一次连续触摸最多切换一个模式。抬手后再次滑动才能继续切换。
“无模式”使用协议原有的 `SPI_MODE_WIREED=0` 编码；SLE 和 DLNA 分别使用
`SPI_MODE_SLE`、`SPI_MODE_DLNA`。

滑条保留原有相对滑动算法：驱动比较相邻帧的触点进入/离开方向，经过积分阈值过滤后
输出 `+100` 或 `-100` 的相对步进。UI 只使用相邻步进差值，绝不把手指的绝对落点
映射为参数值。因此手指可以抬起后重新落下并继续同方向滑动，逐步把音量或亮度调到
`0..100`。当前灵敏度为一次完整滑程约改变 50。

## 3. 引脚和触点映射

当前代码配置：

| 信号 | WS63 GPIO |
|---|---|
| SCL | GPIO12 |
| SDO | GPIO00 |

TTP229 输出使用低电平有效的 16 键模式。

功能键使用 1-based 芯片 pad 编号：

```cpp
PAD_FUNC_A = 7;
PAD_FUNC_B = 6;
PAD_FUNC_C = 5;
```

滑条从左到右的 pad 顺序：

```cpp
PAD_SLIDER[8] = {10, 12, 9, 11, 15, 16, 1, 2};
```

若实物左右方向相反，只需反转 `PAD_SLIDER` 数组。

## 4. 功能键消抖

每个功能键维护稳定状态、消抖计数和短暂保持时间。确认按下后产生一个按下边沿，
`ttp_task` 将边沿锁存，`ui_task` 通过 `ttp_consume_press_latch()` 读取并清除，因此一次
短按只执行一次功能。

同时按下多个功能键时，UI 按 A、B、C 的顺序只处理其中一个。

## 5. SPI 与持久化

UI 通过下列统一更新接口修改设置：

- `spi_settings_update_mode()`
- `spi_settings_update_volume()`
- `spi_settings_update_brightness()`
- `spi_settings_update_hotspot_network()`

这些接口同时标记 NV 配置为待保存。`spi_slave_task` 已在 `main.cpp` 中启用，本地设置
会通过 DWS 链路同步到接收端。
