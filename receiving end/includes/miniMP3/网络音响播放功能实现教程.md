# 海思 WS63 网络音响播放功能实现指南：基于解耦回调与外挂任务的 HTTP 拉流与解码

## 1. 当前业务架构与策略说明

经过设计重构，我们采用**高内聚、低耦合**的架构，利用回调函数（函数指针）彻底打破各模块之间的硬编码依赖，并将RTOS任务创建剥离出核心组件：
1. **DLNA 核心 (`dlan.cpp`)**：处理 UPnP 协议，收取手机发出的播放指令。
2. **网络工具集 (`http_utils.cpp`)**：与业务无关的网络基础函数。
3. **流媒体与解码引擎 (`minimp3.hpp` / `.cpp`)**：这负责**网络 HTTP 拉流 + 在途解码**。最重要的一点：**它绝不 `#include "iis.hpp"`**！为了让它成为一个纯粹的、可移植的黑盒引擎，对声卡的波特率修改、音频灌入，均通过**注册函数指针（回调提供）**来实现。更进一步，**它不再自己调用 `osal_kthread_create` 创建任务**，而是暴露一个死循环函数，由外部 RTOS 环境挂载运行。
4. **音频输出端 (`iis`)**：只负责将拿到的纯 PCM 信号驱动 DMA 播出去。由外层（如 `main.cpp` 或 `dlan` 收到信息处）统一将 `iis` 的 API 以函数指针的形式挂载进 `minimp3` 中。

## 2. 详细实操：在 `minimp3` 中构建无依赖拉流解码链

### 步骤一：使用函数指针定义 `minimp3.hpp` 的跨界通信接口
我们用静态函数指针和注册接口，预留好呼叫底层硬件的通道，并暴露用于外部线程的主循环函数。

```cpp
// minimp3.hpp
#ifndef __MINIMP3_H__
#define __MINIMP3_H__

extern "C" {
#define MINIMP3_IMPLEMENTATION
#include "miniMP3/minimp3.h"
#include "soc_osal.h" 
}
#include "../http_utils.cpp/http_utils.hpp"
#include <array>

class minimp3 {
private:
    static std::array<char, 512> current_url;

public:
    minimp3() {}

    // 【1. 依赖注入预留】注册与音频硬件通信的函数指针
    using iis_set_rate = void (*)(int rate);
    static void iis_set_rate_set(iis_set_rate set_rate_func);

    using mp3_get_into_iis = void (*)(const int16_t *data, uint32_t size);
    static void mp3_get_into_iis_set(mp3_get_into_iis get_into_iis_func);

    // 【2. 对外控制接口】
    static void play_url(const char* url);
    static void stop();
    
    // 【3. 供外部OS/RTOS统一拉起的常驻Task循环】
    static void stream_play_task();

private:
    // 静态变量管理解码状态和回调地址
    static bool is_playing;
    static bool url_ready;
    static iis_set_rate iis_set_rate_func;
    static mp3_get_into_iis mp3_get_into_iis_func;
};

#endif
```

### 步骤二：在 `minimp3.cpp` 中完整实现拉流与回调以及静默循环机制

此时你的 `minimp3.cpp` **无需引入** `iis.hpp`。遇到要向声卡发数据的环节，直接调用被注册好进来的函数指针即可。另外，播放接口 `play_url` 仅修改标志位，而 `stream_play_task` 将通过监测标志位来进行空循环或实际工作。

```cpp
// minimp3.cpp 内部实现
#include "minimp3.hpp"

// 初始化静态成员变量
std::array<char, 512> minimp3::current_url = {0};
bool minimp3::is_playing = false;
bool minimp3::url_ready = false;
minimp3::iis_set_rate minimp3::iis_set_rate_func = nullptr;
minimp3::mp3_get_into_iis minimp3::mp3_get_into_iis_func = nullptr;

void minimp3::iis_set_rate_set(iis_set_rate set_rate_func) {
    iis_set_rate_func = set_rate_func;
}

void minimp3::mp3_get_into_iis_set(mp3_get_into_iis get_into_iis_func) {
    mp3_get_into_iis_func = get_into_iis_func;
}

void minimp3::play_url(const char* url) {
    if (url == nullptr) return;
    
    // 拷贝URL到共享变量
    strncpy(current_url.data(), url, current_url.size() - 1);
    current_url[current_url.size() - 1] = '\0';
    
    // 设置标志位，唤醒后台常驻的任务去连接网络
    is_playing = true;
    url_ready = true;
}

void minimp3::stop() {
    is_playing = false; // 这会导致一轮流水线退出，并回到任务的空循环等待
    url_ready = false;
}

// 核心：下载 + 解码 + 回调推送 的一条龙同步流水线
void minimp3::stream_play_task() {
    // 提前准备好解码器组件（放在循环外，节省内层重复分配）
    mp3dec_t mp3d;
    mp3dec_frame_info_t info;

    const int INBUF_SIZE = 8192; 
    uint8_t *in_buf = (uint8_t *)osal_kmalloc(INBUF_SIZE, OSAL_GFP_KERNEL);
    int16_t *pcm_buf = (int16_t *)osal_kmalloc(MINIMP3_MAX_SAMPLES_PER_FRAME * sizeof(int16_t), OSAL_GFP_KERNEL);

    // 大循环：Task 作为一个常驻进程运行
    while (true) {
        if (!url_ready) {
            // 没有活干的时候，休眠交出CPU
            osal_msleep(100); 
            continue;
        }

        // ==========================================
        // 1. 【网络准备】解析 URL 并建立 Socket 连接
        // ==========================================
        url_ready = false; // 消费掉标记
        int current_hz = 0;
        int bytes_in_buf = 0;
        mp3dec_init(&mp3d);
        
        simple_http_url url_parsed;
        if (!parse_http_url(current_url.data(), url_parsed)) { continue; }

        int32_t sock = socket(AF_INET, SOCK_STREAM, 0);
        if (sock < 0) continue;

        // 设置接收超时时间
        timeval tv = {3, 0}; // 3秒超时
        setsockopt(sock, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv));

        sockaddr_in addr = {0};
        addr.sin_family = AF_INET;
        addr.sin_port = htons(url_parsed.port);
        if (!resolve_ipv4_addr(url_parsed.host.data(), &addr.sin_addr)) { 
            lwip_close(sock); 
            continue; 
        }

        if (connect(sock, (sockaddr *)&addr, sizeof(addr)) != 0) { 
            lwip_close(sock); 
            continue; 
        }

        // ==========================================
        // 2. 【发送 HTTP GET 请求】请求拉取长连接流
        // ==========================================
        char request[512];
        snprintf(request, sizeof(request),
                 "GET %s HTTP/1.1\r\n"
                 "Host: %s\r\n"
                 "Connection: keep-alive\r\n"
                 "Icy-MetaData: 0\r\n\r\n", 
                 url_parsed.path.data(), url_parsed.host.data());
        
        if (lwip_send(sock, request, strlen(request), 0) <= 0) {
            lwip_close(sock);
            continue;
        }

        // 逐字节接收数据以跳过 HTTP Header，直到匹配到 "\r\n\r\n"
        char header_buf[1];
        int matched = 0;
        bool header_passed = false;
        while (is_playing) {
            int ret = lwip_recv(sock, header_buf, 1, 0);
            if (ret <= 0) break; // 接收超时或对端关闭连接
            
            if (header_buf[0] == '\r' && matched == 0) matched = 1;
            else if (header_buf[0] == '\n' && matched == 1) matched = 2;
            else if (header_buf[0] == '\r' && matched == 2) matched = 3;
            else if (header_buf[0] == '\n' && matched == 3) {
                header_passed = true;
                break;
            } else {
                // 如果当前正好是 \r，说明可能是一个新的匹配起点
                matched = (header_buf[0] == '\r') ? 1 : 0;
            }
        }

        if (!header_passed) {
            lwip_close(sock);
            continue; // Header 接收失败，直接进入下一轮重试
        }

        // 此处注意：IIS的清空 data_clear 操作不再由这里实现。可以在上层（如 dlan ）调用 play_url 前先清空 IIS。

    // ==========================================
    // 3. 【核心流水线：网络接收 -> 解码 -> 通过回调注入声卡栈】
    // ==========================================
    while (is_playing) {
        // A. 若内存还有空位置，先从网络里把数据吸进来
        if (bytes_in_buf < INBUF_SIZE) {
            int recv_len = lwip_recv(sock, in_buf + bytes_in_buf, INBUF_SIZE - bytes_in_buf, 0);
            if (recv_len <= 0) break; // 音频流完毕，掉线了结束一切
            bytes_in_buf += recv_len;
        }

        // B. 一鼓作气解一帧（凑不够整帧返回0；凑够了吐出 PCM）
        int samples = mp3dec_decode_frame(&mp3d, in_buf, bytes_in_buf, pcm_buf, &info);

        if (samples > 0) {
            // C. 若音频采样率变更，而且外边注册了修改时钟的函数指针，便触发之
            if (info.hz != current_hz && info.hz != 0) {
                current_hz = info.hz;
                if (iis_set_rate_func) {
                    iis_set_rate_func(current_hz);
                }
            }

            // D. 【核心水桶堵塞点】调用外部注册的数据推送接口
            // 由于外部的 iis 缓冲区一旦填满就会阻塞此指针的返回，进而阻塞了整个任务去拉取下一个网络包。
            if (mp3_get_into_iis_func) {
                mp3_get_into_iis_func(pcm_buf, samples * info.channels);
            }
        }

        // E. 网络半帧数据尾巴保护算法 (滑动窗口前移)
        if (info.frame_bytes > 0 && info.frame_bytes <= bytes_in_buf) {
            bytes_in_buf -= info.frame_bytes;
            memmove(in_buf, in_buf + info.frame_bytes, bytes_in_buf);
        }
    }

    // ==========================================
    // 4. 【单曲播放结束/被切歌：闭环收尾】
    // ==========================================
        lwip_close(sock); 
        is_playing = false; // 切回沉睡状态
    }

    // Task 原则上永远不应该退出（死循环），如果退出了才走这一步清内存
    osal_kfree(in_buf);
    osal_kfree(pcm_buf);
}
```

### 步骤三（新增）：在拉流链路中使用 `extract_http_header_value` 解析响应头

上面的示例是“只跳过响应头再解码”。现在你已经有了通用函数 `extract_http_header_value(...)`，建议把响应头先收集到一个缓冲区，再按需提取字段。这样你可以在真正喂给解码器前做协议校验和兼容处理。

典型接法如下：

```cpp
// 先把HTTP响应头读全（直到 \r\n\r\n），再统一解析
std::array<char, 1024> resp_header = {0};
int header_len = 0;
bool header_ok = false;

while (is_playing && header_len < static_cast<int>(resp_header.size()) - 1) {
    int ret = lwip_recv(sock, resp_header.data() + header_len, 1, 0);
    if (ret <= 0) {
        break;
    }
    header_len += ret;
    resp_header[header_len] = '\0';

    if (header_len >= 4 && strstr(resp_header.data(), "\r\n\r\n") != nullptr) {
        header_ok = true;
        break;
    }
}

if (!header_ok) {
    lwip_close(sock);
    continue;
}

// 用通用函数按键提取头字段（大小写不敏感）
std::array<char, 128> content_type = {0};
std::array<char, 64> transfer_encoding = {0};

bool has_content_type = extract_http_header_value(
    resp_header.data(), "Content-Type", content_type.data(), content_type.size());
bool has_transfer_encoding = extract_http_header_value(
    resp_header.data(), "Transfer-Encoding", transfer_encoding.data(), transfer_encoding.size());

if (has_content_type) {
    trim_ascii_whitespace(content_type.data());
    osal_printk("HTTP Content-Type: %s\n", content_type.data());
}

if (has_transfer_encoding) {
    trim_ascii_whitespace(transfer_encoding.data());
    osal_printk("HTTP Transfer-Encoding: %s\n", transfer_encoding.data());
}
```

在你这个音频场景里，至少建议读取并判断这几项：
1. `Content-Type`：是否为 `audio/mpeg` 或可接受类型。
2. `Transfer-Encoding`：若为 `chunked`，后续要做 chunk 解包，不能直接把整段字节流当纯 MP3 喂解码器。
3. `ICY` / 相关头：部分电台流会带 ICY 头，先识别再决定是否跳过元数据。

这样做的收益是：出现“能连上但无声”时，你可以快速判定是协议层问题还是解码层问题。

## 3. 回调注入式架构与外挂任务的优势（原理解读）

**1. 完美的控制反转（IoC / 依赖注入）**
通过 `iis_set_rate_func` 和 `mp3_get_into_iis_func` 两个函数指针，`minimp3` 从一个原本又得懂网络、又得懂硬件的“胖模块”，变成了一个**纯粹提供「网络播放流拉取及解码服务」的黑匣子**。你可以随时把这个引擎移植到其它不使用 `iis` 库的项目，或者以后使用其他的喇叭驱动方案，`minimp3` 的代码**一行都不用改**！

**2. 任务隔离，控制权归还系统**
`minimp3` 内部不再乱弹线程 (`osal_kthread_create`)，它只暴露一个死循环工作函数 `stream_play_task()`。这样做的好处是系统的任务优先级和栈大小可以由上层应用统一管理和监控，避免了组件内部隐藏地消耗系统资源这等麻烦事。外层启动一个线程去跑这套逻辑即可。

**3. 在外围总控（如 `main` 函数 中）注册并驱动**

我们在负责总体接管的模块只需要挂载好：

```cpp
// 假设这是 main.cpp 或者系统的总初始化文件
#include "minimp3.hpp"
#include "iis.hpp"

// 任务包装器
static int my_audio_thread(void* arg) {
    minimp3::stream_play_task();
    return 0;
}

// 提供符合规约类型的回调函数：
void my_audio_rate_set(int rate) {
    // 你的枚举映射逻辑
    iis::set_rate_of_iis( (i2s_sample_rate_t)rate ); 
}
void my_audio_data_write(const int16_t *data, uint32_t size) {
    iis::data_write(data, size); 
}

void system_init() {
    // 1. 将音频驱动 API 注册进解码端
    minimp3::iis_set_rate_set(my_audio_rate_set);
    minimp3::mp3_get_into_iis_set(my_audio_data_write);

    // 2. 将主循环抛入独立的线程跑起来
    osal_kthread_create("Audio_Task", my_audio_thread, nullptr, OSAL_TASK_PRIORITY_APP, 4096);
}

// 在 dlan 收到播放动作时：
void on_dlan_play(const char* url) {
    iis::data_clear();         // 播放前将上首音乐遗留的缓存清理掉
    minimp3::play_url(url);    // 只唤醒标志位，后台空转的任务会接管
}
```

**4. 天作之合的“水桶”同步流控核心不曾改变**
哪怕使用了函数指针，只要挂载的 `my_audio_data_write` 内部有阻塞逻辑（当 DMA 的 100个缓存发满时暂停写入），那么在函数指针调用执行期间整个大的 `while` 循环依然会被死死卡住，`lwip_recv` 也被迫暂停接网络包，完美的**背压同步（Backpressure）机制**依旧成立。
